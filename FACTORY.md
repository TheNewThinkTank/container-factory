# Factory contract

An image definition is a directory under `images/` containing:

- `Dockerfile`
- `metadata.yaml`

The metadata contract is:

```yaml
name: <lowercase image name>
version: <semver>
description: <human-readable description>
dockerfile: Dockerfile
architectures:
  - linux/amd64
  - linux/arm64
registry:
  - ghcr
```


> **v2.1.1:** The reusable workflow intentionally declares no elevated `GITHUB_TOKEN` permissions. Callers grant only the permissions they need: CI is read-only; Release grants package publishing and OIDC signing.

## v2 artifact contract

A published image has two identities:

- a mutable human-facing tag such as `:3.14.7`;
- an immutable OCI digest such as `@sha256:...`.

Security decisions are made against the immutable digest.

The release build produces a multi-platform OCI image and attaches:

- an SPDX SBOM attestation generated by BuildKit;
- max-level BuildKit provenance in in-toto/SLSA provenance format.

The digest returned by the Buildx build step is treated as the image-index
digest. GHCR may expose attached attestations as separate OCI referrer
artifacts (including `sha256-<digest>`-style tags); those referrer digests are
not treated as image identities by the factory.

BuildKit supports these attestations directly during a registry push.

## Security gate

The factory uses Grype to produce vulnerability reports and a Python policy
module to decide whether publication is acceptable.

The release workflow scans the exact `linux/amd64` and `linux/arm64` child
manifests referenced by the published multi-architecture digest. This avoids
silently scanning a separate locally rebuilt artifact.

## Signing contract

After the security gate passes, Cosign signs the exact multi-architecture
image digest using GitHub Actions OIDC and Sigstore keyless signing.

The workflow then verifies the signature against:

```text
https://github.com/<owner>/<repository>/.github/workflows/reusable-container.yml@refs/heads/main
```

and the Sigstore token issuer:

```text
https://token.actions.githubusercontent.com
```

This means the trust decision is bound to the release workflow identity rather
than a long-lived private signing key.

## CI and release workflows

CI and Release are separate workflow entry points with different trust levels. CI validates, tests, builds, and scans without publishing or signing. Release builds the multi-platform artifact, publishes it, performs the digest-based security gate, signs it, and verifies the resulting trust metadata.

The implementation is shared by `.github/workflows/reusable-container.yml`. This prevents the build and scan logic from drifting between CI and Release while keeping the release workflow’s elevated `packages: write` and `id-token: write` permissions isolated to the release caller.

## Release flow

```text
metadata validation
        ↓
Buildx multi-arch build + push
        ↓
SBOM attestation
        ↓
provenance attestation
        ↓
validate image index + platforms
        ↓
immutable image-index digest
        ↓
scan exact platform manifests
        ↓
security policy
        ↓
Cosign keyless signature
        ↓
Cosign verification
        ↓
SBOM + SLSA provenance verification
```

A failed security gate prevents signing. An unsigned artifact therefore cannot
pass the factory's final signing step.

## Local usage

```bash
make setup
make validate
make test
make build IMAGE=python
make sbom IMAGE=python
make scan IMAGE=python
```

For a published image:

```bash
make inspect REGISTRY_IMAGE=ghcr.io/thenewthinktank/python
```

and verify a known digest:

```bash
export COSIGN_CERTIFICATE_IDENTITY='https://github.com/TheNewThinkTank/container-factory/.github/workflows/reusable-container.yml@refs/heads/main'
make verify IMAGE=python DIGEST=sha256:<digest>
```

## Design principles

### Digest is the identity

Tags are references. The digest is the exact artifact that is scanned and
signed.

### Build metadata travels with the artifact

SBOM and provenance are attached to the image instead of being treated only as
CI files. This lets downstream consumers inspect the artifact's supply-chain
metadata where it is consumed.

### Sign after the security gate

The factory does not sign an image until its configured vulnerability policy
passes.

### Keep the factory boring

v2 uses Docker BuildKit, Syft/Grype, Sigstore/Cosign and a small Python policy
module. It does not yet introduce an admission controller, registry promotion
system, or custom signing infrastructure.
